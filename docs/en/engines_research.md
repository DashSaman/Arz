# Engines and evidence: a design decision for Arz

**Reviewed: 13 October 2026, UTC. Real trading: DISABLED.** Arz's experimental capital ceiling is **$100**, with spot markets only, no leverage, no martingale and no replenishment. This research required no trading capital, account connection, wallet, private key, purchase or installation of an upstream bot.

## Recommendation

Keep the initial Arz implementation as an **original, MIT-licensed, standard-library Python research harness**. Its job is to ingest clearly identified data, apply deterministic rules, model a bounded virtual portfolio and produce reproducible evaluation records. A wallet or signing interface adds no value to that experiment.

Use **Freqtrade as an optional external benchmark** once Arz's baseline and cost assumptions are fixed. Treat **Hummingbot Gateway as a future quote-adapter candidate**, with execution disabled and a fresh source/configuration security review before adoption. Retain **trade-executor** as a DeFi-specific research alternative. LEAN and NautilusTrader become attractive only when their richer execution or multi-asset models solve a demonstrated problem. These are engineering judgments based on the documented scopes; they are not rankings of expected returns. ## Capabilities that matter for the experiment

**Freqtrade** offers a practical Python, candle-based research workflow with dry-run, fee modeling and diagnostics. Its current README lists Hyperliquid **spot**, so “Freqtrade has no DEX support” would be wrong. That connector does not imply general EVM/Solana AMM routing. Ordinary backtests assume requested-price fills without slippage when the price is inside the candle; historic exchange limits are not fully available. These differences make it a comparison tool, not ground truth. [E01](https://raw.githubusercontent.com/freqtrade/freqtrade/e35b93cbb4cd1f87ae5699d01f7996e569a7a753/README.md) [E04](https://www.freqtrade.io/en/stable/backtesting/) [E07](https://www.freqtrade.io/en/stable/exchanges/)

**FreqAI** adds predictive modeling and adaptive retraining to the same engine. Its sliding training/backtest windows are useful, but feature creation can still leak future information. The example is explicitly unsuitable for production, and its JOSS publication reviews software rather than an independently verified profitable strategy. Defer it until a non-ML baseline, targets, availability timestamps and evaluation windows are fixed. **freqtrade-strategies** supplies educational hypotheses; source availability alone is not a validated backtest. [E02](https://www.freqtrade.io/en/stable/freqai/) [E06](https://www.freqtrade.io/en/stable/freqai-running/) [E08](https://joss.theoj.org/papers/10.21105/joss.04864) [E03](https://raw.githubusercontent.com/freqtrade/freqtrade-strategies/f3340ce11f5bdf62f598522e64d1f5638eaa13f5/README.md)

**Hummingbot** is oriented toward execution and market making, with CEX, CLOB DEX and Gateway-mediated AMM connectivity. Selected paper strategies need no exchange credentials, but their generous default virtual balances must be replaced by the actual experiment budget. V2 controller backtesting does not establish faithful simulation of every connector or inventory strategy. The README's aggregate trading volume is not strategy P&L. Its AI ecosystem includes the separate Condor/API stack, not a supplied proven edge. [E09](https://raw.githubusercontent.com/hummingbot/hummingbot/9af100d6822da7d2d0291a906c730ef172284ee2/README.md) [E10](https://hummingbot.org/client/global-configs/paper-trade/)

**Gateway** is independently useful because it can run as a standalone REST service with Router, AMM and concentrated-liquidity schemas. It also holds wallet keys and exposes fund-moving functions. For Arz, the relevant future interface is a normalized quote with chain, asset identifiers, amounts, route, fees, timestamp and expiry. No route should implicitly grant execution authority. Gateway is neither a complete strategy nor a standalone strategy backtester. [E11](https://hummingbot.org/gateway/) [E12](https://hummingbot.org/gateway/connectors/)

**OctoBot** offers a visual workflow, spot connectors including Hyperliquid, and OpenAI/Ollama/custom-model evaluators. Its beta node architecture can launch manual instances for backtesting. GPT predictions act as indicators, and historical GPT backtests depend on selected supplied prediction histories. Neither model confidence nor a retrospective answer establishes calibrated probability or causal availability. Its UI, node identity and plugin layers add more dependencies than this MVP needs. [E17](https://raw.githubusercontent.com/Drakkar-Software/OctoBot/c45fdc2c95c5bd3d649251fa90c327e2e8f86b00/README.md) [E18](https://www.octobot.cloud/en/guides/octobot-usage/backtesting) [E19](https://www.octobot.cloud/en/guides/octobot-trading-modes/chatgpt-trading) [E20](https://www.octobot.cloud/en/guides/octobot)

**Jesse** now documents a built-in ML pipeline, research API, Monte Carlo and significance-testing workflows; reinforcement learning is still advertised as coming soon. Its MIT core must be separated from commercial features. Current pricing includes free backtesting/ML, but **no free paper trading or DEX support**; Basic Lifetime is **$899**. Thus free research remains a possible comparison, while the advertised paid paper/live path exceeds this experiment's envelope. [E21](https://raw.githubusercontent.com/jesse-ai/jesse/5e642997f9623d67b63543962eab46caca30e613/README.md) [E22](https://jesse.trade/pricing) [E23](https://docs.jesse.trade/docs/research/ml/)

**LEAN** has broad event-driven modeling and ML-library integration. Coinbase's cash model establishes spot capability; its dYdX model supports **crypto futures**, which is outside Arz's scope. The Apache engine can be built locally, while the official LEAN CLI requires a paid-tier organization. This distinction matters when someone calls the whole workflow “free.” Multi-asset breadth and setup effort are unnecessary until a concrete research requirement justifies them. [E24](https://raw.githubusercontent.com/QuantConnect/Lean/80e7843f645673bcbeaab963049f76f20f6785e1/readme.md) [E25](https://www.quantconnect.com/docs/v2/lean-cli/key-concepts/getting-started) [E26](https://www.quantconnect.com/docs/v2/writing-algorithms/machine-learning/popular-libraries/scikit-learn) [E27](https://www.quantconnect.com/docs/v2/writing-algorithms/reality-modeling/brokerages/supported-models/dydx) [E28](https://www.quantconnect.com/docs/v2/writing-algorithms/reality-modeling/brokerages/supported-models/coinbase)

**NautilusTrader** is attractive for deterministic event-level simulation, richer market data and shared research/live strategy code. It documents Hyperliquid spot execution, but is undergoing a substantial v2 transition. The project explicitly excludes built-in ML tooling from its stated open-source scope; being suitable for AI-agent training is a different capability. Its integration guide also describes a mainnet-history prerequisite for the Hyperliquid testnet faucet, so “testnet” cannot automatically mean a wallet-free experiment. [E29](https://raw.githubusercontent.com/nautechsystems/nautilus_trader/fb53ee6a420570a76af04fc4835f2122c3c6d6fb/README.md) [E30](https://nautilustrader.io/docs/latest/integrations/hyperliquid/)

**Trading Strategy's trade-executor** is the strongest additional DeFi-specific comparison here: Python strategies, historical simulation and live execution around supported decentralized venues. Its early-beta warning, data/RPC dependencies and AGPL license matter. A market-data listing does not establish every execution route. It is useful for future DeFi research, while a fresh data-quality and cost-model review should precede any dependency decision. ## Security evidence and practical limits

Gateway issue **652** reports wallet-exposure risks and an incident on the reporter's node. PR **659** merged on 2 July 2026; GitHub ancestry confirms it is included in the captured **v2.17.0** commit. Further issue **660** remains open. Current wallet registration has no explicit raw-key export route, so an old open checklist cannot be treated as a precise inventory of current vulnerabilities. The review verified selected source and ancestry, not the reported loss, complete route protection or every deployment configuration. ## What $100 can and cannot establish

An offline experiment needs no trading capital and can use existing compute without buying a service. A funded strategy would face venue minimums, rounding, spreads, maker/taker fees, RPC costs, native network fees, approvals and failures. Solana's documented base fee is only one component; Uniswap pool fees exclude gas and execution impact. No universal current minimum deposit or all-in transaction cost was established. [E04](https://www.freqtrade.io/en/stable/backtesting/) [E41](https://solana.com/docs/core/fees) [E42](https://docs.uniswap.org/concepts/protocol/fees)

Consider an **illustrative calculation, not a quote**: a $25 round trip with 0.10% fee per side, 0.10% slippage per side and $0.50 total chain cost consumes $0.60, or **2.4% of that position**, before profit. A hypothetical $5 monthly service alone equals 5% of $100. Lower fixed costs help, but do not create predictive edge. Fragmenting $100 across venues or liquidity inventories also makes minimum sizes and stranded balances more consequential. Nothing in these features proves economical growth from $100.

## Evidence levels and research protocol

These are the user's internal evidence definitions, not a published industry standard:

| Level | Required evidence |
|---:|---|
| 0 | Marketing without data |
| 1 | Published backtest without reproducibility |
| 2 | Reproducible backtest |
| 3 | Out-of-sample **and** walk-forward |
| 4 | Live paper trading |
| 5 | Checkable real trading |
| 6 | Long-term independent validation across regimes |

**UNTESTED** is appropriate for inspectable code or a hypothesis without an evaluated result. A functioning API capture, a synthetic fixture or a short paper smoke test does not establish strategy performance. The reviewed engine features provide no automatic Level 3–6 qualification for an Arz candidate. The performance ledger labels illustrative published results separately from capability claims.

The NBER cryptocurrency study motivates momentum as a hypothesis. Indexed primary PDF text reports BTC predictor associations of 0.33 percentage points for next-day returns and 3.16 for next-week returns per one-standard-deviation predictor movement. These are historical associations, not net executable ROI or current forecasts; direct full-PDF retrieval returned 403, so complete sample/table replication was not established. [E40](https://www.nber.org/papers/w24877.pdf)

The statistical priority is controlling selection and leakage. PBO research explains why selecting the best of many backtests can select noise; the Deflated Sharpe Ratio addresses selected maxima and non-normal returns. scikit-learn demonstrates apparent 0.76 accuracy on random labels falling to 0.50 after correct feature selection. That synthetic example illustrates leakage, not trading performance. Chronological splits need training-only transformations, availability-aware features and gaps/purging matched to label horizons. [E36](https://www.davidhbailey.com/dhbpapers/backtest-prob.pdf) [E37](https://www.davidhbailey.com/dhbpapers/deflated-sharpe.pdf) [E38](https://scikit-learn.org/stable/common_pitfalls.html) [E39](https://scikit-learn.org/stable/modules/generated/sklearn.model_selection.TimeSeriesSplit.html)

Arz should therefore preserve dataset hashes and provenance, rule/configuration versions, every attempted parameter set, chronological training/validation/test windows, all fees and an explicit benchmark. Evaluate cash and buy-and-hold baselines on identical data and costs, report turnover/drawdown and missing observations, and stress worse fills. Freeze the evaluation protocol before comparing ML. A diagnostic pass such as Freqtrade's lookahead analysis is useful but only checks triggered signals under its assumptions. [E05](https://www.freqtrade.io/en/stable/lookahead-analysis/)

## Licensing and the next integration decision

Arz's original code is MIT, with **no upstream code imported or vendored**. Freqtrade, its strategy collection and OctoBot carry GPLv3-family licenses; Nautilus declares LGPL-3.0-only; Hummingbot, Gateway and LEAN use Apache-2.0; Jesse's core is MIT. trade-executor's API metadata says NOASSERTION, but its actual license explicitly says **AGPL-3.0-or-later**. Preserve notices and review obligations before any future copying or linking; a process or REST boundary does not automatically settle copyleft scope. [E49](https://www.apache.org/licenses/LICENSE-2.0) [E51](https://raw.githubusercontent.com/freqtrade/freqtrade/e35b93cbb4cd1f87ae5699d01f7996e569a7a753/LICENSE) [E52](https://raw.githubusercontent.com/nautechsystems/nautilus_trader/fb53ee6a420570a76af04fc4835f2122c3c6d6fb/LICENSE) [E53](https://raw.githubusercontent.com/jesse-ai/jesse/5e642997f9623d67b63543962eab46caca30e613/LICENSE) [E54](https://raw.githubusercontent.com/spdx/license-list-data/main/text/AGPL-3.0-or-later.txt)

The next justified work is reproducible offline evaluation. Add an external engine only when a documented mismatch cannot be resolved economically in the harness: Freqtrade for candle-result comparison, Gateway for read-only DEX quotes, trade-executor for DeFi historical research, Nautilus for event-level execution, or LEAN for broader asset classes. None of these decisions enables real trading or changes the $100, spot-only constraints.
