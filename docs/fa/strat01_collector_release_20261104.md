# آماده‌سازی انتشار و بازیابی Collector — ۴ نوامبر ۲۰۲۶

**بسته برای بازبینی آماده می‌شود؛ هیچ سرور کاربر مستقر نشده، هیچ درخواست تازه‌ای به بازار انجام نشده و هیچ سرمایه‌ای مجاز نیست.** این همان Collector مشاهدهٔ فقط‌خواندنی است؛ استراتژی تأییدشده اجرا نمی‌کند و کیف‌پول، امضا یا دورهٔ Paper Trading ندارد.

## هویت نسخه و پیش‌فرض امن

تصویر رسمی Python در `deploy/collector/docker-compose.yml` با digest ثابت `sha256:e697c81897302a4c4333bade000d98038fbb21eb064f8ee1fd42d02ebcd9d337` قفل شده است. [رکورد رسمی در کامیت ثابت c420411](https://github.com/docker-library/repo-info/blob/c42041158bdc54accabfa176497df786dcdd905b/repos/python/remote/3.12-slim-bookworm.md) نسخهٔ 3.12.16 و هویت جداگانهٔ manifest/image معماری amd64 را اعلام می‌کند. زمان دریافت و هش منبع در `deploy/collector/image-provenance.json` است. خواندن این رکورد به معنی دانلود یا اجرای واقعی کانتینر نیست. محیط محلی Docker/Podman ندارد؛ اجرای واقعی workflow جدید باید جداگانه از نتیجهٔ CI تأیید شود.

فایل پایهٔ Compose علاوه بر غیرفعال‌بودن شبکه در برنامه، اکنون **`network_mode: none`** دارد. کاربر کانتینر UID/GID 65534 است؛ ریشه و سورس فقط‌خواندنی‌اند، قابلیت‌های اضافی حذف شده و منابع محدودند. لاگ‌ها حداکثر سه فایل ۵ مگابایتی دارند. فقط `/data` و فضای موقت محدود قابل‌نوشتن‌اند و پورتی منتشر نمی‌شود. فایل جداگانهٔ `docker-compose.readonly-network.yml` تنها پس از تأیید میزبان و دسترسی ارائه‌دهنده، شبکهٔ دریافت داده را فعال می‌کند؛ مجری معامله‌ای اضافه نمی‌کند.

علاوه بر تصویر، سورس هم باید ثابت باشد: در میزبان جداگانه و مجاز، کامیت بررسی‌شده را با `git archive <APPROVED_COMMIT>` در پوشهٔ انتشار جدید استخراج کنید. checkout در حال تغییر، پوشهٔ پروژهٔ دیگر یا پوشهٔ دارای secret را mount نکنید. SHA کامیت، هش آرشیو سورس، RepoDigests، image ID، معماری و نسخهٔ Python ثبت شوند. این بررسی digest به معنی ممیزی کامل آسیب‌پذیری یا امضای زنجیرهٔ تأمین نیست.

## شروع احتمالی روی میزبان

دستورهای این بخش روی سرور کاربر اجرا نشده‌اند. تأیید جداگانه باید میزبان، ارائه‌دهنده‌های مجاز، مسیر داده، نگهداری و مسئول اجرا را مشخص کند. ساعت UTC، فضای دیسک، مالکیت فایل‌ها، نسخهٔ Docker/Compose و مجازبودن منبع داده بررسی شوند. سابقهٔ HTTP 429 عمومی Base همچنان مانع دسترسی است؛ فعال‌سازی شبکه مجوز تکرار یا دورزدن محدودیت نیست.

از ریشهٔ نسخهٔ بررسی‌شده:

```sh
mkdir -p runtime/arz-collector/forward runtime/arz-collector/events
sudo chown -R 65534:65534 runtime/arz-collector
sudo chmod 700 runtime/arz-collector runtime/arz-collector/forward runtime/arz-collector/events
docker compose -f deploy/collector/docker-compose.yml config
docker compose -f deploy/collector/docker-compose.yml up -d --wait
docker compose -f deploy/collector/docker-compose.yml exec -T arz-readonly-collector python -m scripts.strat01_independent_collector dry-run --data-root /data
```

پیش‌فرض بالا شبکه ندارد. فقط بعد از تأیید جداگانهٔ میزبان/منبع، مسئول اجرا هر دو فایل را به کار می‌برد:

```sh
docker compose -f deploy/collector/docker-compose.yml -f deploy/collector/docker-compose.readonly-network.yml config
docker compose -f deploy/collector/docker-compose.yml -f deploy/collector/docker-compose.readonly-network.yml up -d --force-recreate --wait
```

فایل دوم خروجی عادی شبکهٔ کانتینر را مجاز می‌کند؛ allowlist ارائه‌دهندگان نیست. اعمال سیاست شبکهٔ میزبان با مسئول آن است. وجود دستور در سند، شاهد دسترسی مجاز یا اجرای پیوسته نیست.

## پایش، هشدار و توقف

فرمان health برای زنده‌بودن برنامه و مانیتور موجود برای صحت/زمان داده‌ها و طول زنجیرهٔ دو بازار استفاده می‌شود. هیچ‌کدام سوددهی را تأیید نمی‌کنند. HTML/JSON را با `scripts/strat01_local_monitor.py` طبق سند V5 روی حجم اختصاصی بسازید. سلامت فرایند و پوشش واقعی داده را جدا کنترل کنید؛ برنامهٔ زنده ممکن است دادهٔ کافی نداشته باشد.

Docker health به‌تنهایی پیام هشدار ارسال نمی‌کند و کانتینر ناسالم را خودکار restart نمی‌کند. **مسیر تحویل هشدار پیکربندی یا آزموده نشده است**؛ مقصد/اتصال مجاز و تست تحویل واقعی پیش‌نیاز اجرای بدون نظارت‌اند. تا آن زمان، این بسته فقط برای بررسی عملیاتی تحت نظارت و پس از تأیید میزبان مناسب است. خطای پایدار Collector، heartbeat مفقود/کهنه، کندل‌های مفقود، تعارض داده، فشار دیسک یا بازیابی ناقص باید هشدار بدهند. برای سبزشدن مانیتور، خطا یا ساعت منبع پاک/اصلاح نشود.

توقف اضطراری با همان پروژه و مجموعه فایل فعال Compose انجام می‌شود:

```sh
docker compose -f deploy/collector/docker-compose.yml stop
```

کیف‌پولی متصل نیست؛ تطبیق با موجودی حساب واقعی در این نسخه وجود ندارد. مجری احتمالی آینده باید موجودی زنجیره، دارایی گاز و تراکنش‌های معلق را پیش از هر تأیید مالی تطبیق دهد؛ پرتفوی شبیه‌سازی جای آن نیست.

## پشتیبان‌گیری و بازیابی

ابزار جدید `scripts/strat01_collector_backup.py` کاملاً آفلاین است. سرویس را متوقف کنید، حجم اصلی را نگه دارید و ابزار را با مالک داده، یعنی UID 65534 در این استقرار، و با پوشهٔ پشتیبان قابل‌دسترسی **بیرون از حجم داده** اجرا کنید. مسیرهای زیر نمونه‌اند:

```sh
PYTHONPATH=src:. python -m scripts.strat01_collector_backup backup --data-root runtime/arz-collector --archive /approved-backups/arz-evidence-20261104.zip
sha256sum /approved-backups/arz-evidence-20261104.zip
PYTHONPATH=src:. python -m scripts.strat01_collector_backup restore --archive /approved-backups/arz-evidence-20261104.zip --data-root runtime/arz-restored-20261104
```

ساختار منبع/رویداد، مسیر، حدود اندازه و هش هر فایل بررسی می‌شود. قفل نویسنده، symlink، تغییر منبع حین backup، عضو خراب یا خارج از manifest و مقصد/فایل ازقبل‌موجود باعث رد عملیات‌اند. فقط بایت‌ها و زمان‌های اصلی بازیابی می‌شوند؛ **heartbeat و قفل قدیمی بازیابی نمی‌شوند**. اگر نوشتن فایل ناقص ماند، `.restore-incomplete` قرنطینه بماند و سرویس روی آن شروع نشود. هش‌ها سازگاری را کنترل می‌کنند و در برابر میزبان بدخواه گواه اصالت نیستند.

همیشه در پوشهٔ جدید restore کنید. هش آرشیو و برابری فایل‌ها با manifest جدا نگه‌داشته‌شده بررسی شود، مانیتور دوباره ساخته شود و بعد از بازبینی، مسیر جدید به‌صورت آگاهانه انتخاب شود. حجم قبلی و خطاهایش حفظ شوند. آرشیوهای متفاوت یا revisions متعارض خودکار ادغام نشوند. ظرفیت محدود ابزار ۱۲۸ مگابایت پس از بازشدن همراه با سقف‌های موجود تعداد منبع/رویداد است؛ عبور از ظرفیت عملیات را رد می‌کند و هرگز داده حذف نمی‌کند. سیاست فعلی **نگهداری همهٔ منابع/رویدادها** است؛ چرخش لاگ با حذف شاهد فرق دارد. تناوب backup، نگهداری و مقصد خارج میزبان نیازمند تصمیم مسئول اجرا هستند.

### بررسی واقعاً انجام‌شده

- هفت آزمون مصنوعی بازیابی ابتدا به علت نبود ابزار شکست خوردند و سپس موفق شدند: عدم بازنویسی، مسیر ناامن، خرابی، ادعای مالی جعلی با هش تازه، symlink/قفل و حفظ دقیق بایت‌ها.
- هر ۳۵ فایل واقعی موجود در `main` به پوشهٔ آزمایش جدا کپی، پشتیبان‌گیری و بایت‌به‌بایت بازیابی شد. هش ZIP در `source-backup-rehearsal.json` ثبت است. هیچ درخواست بازار، مشاهده یا روز Paper تازه‌ای ایجاد نشد.
- digest تصویر از رکورد ثابت رسمی خوانده شد؛ اجرای Docker محلی ممکن نبود.
- workflow جدید `.github/workflows/strat01-collector-release.yml` راه‌اندازی/health/جداسازی واقعی Compose را روی runner موقت CI با شبکهٔ خاموش بررسی و هویت واقعی تصویر را ذخیره می‌کند. وضعیت اجرا باید از شواهد CI تحویلی خوانده شود، نه صرفاً وجود فایل.

## بازگشت نسخه

سرویس متوقف، دادهٔ فعلی پشتیبان‌گیری و حفظ، سورس و تصویر قبلیِ بررسی‌شده انتخاب، و ابتدا شبکه خاموش اجرا شود. سازگاری داده/schema و خطاها پیش از دسترسی فقط‌خواندنیِ ازقبل‌مجاز بررسی شوند. تغییر مؤثر استراتژی/کد/تنظیمات به بررسی فنی و دورهٔ آینده‌نگر با شناسهٔ جدا نیاز دارد. بازگشت کد داده‌های قدیمی را آینده‌نگر نمی‌کند؛ پاک‌سازی خودکار یا فعال‌سازی مالی بخشی از rollback نیست.
