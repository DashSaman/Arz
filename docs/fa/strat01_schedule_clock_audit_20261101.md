# STRAT-01 — ممیزی واقعی ساعت اجرای GitHub Actions، ۱ نوامبر ۲۰۲۶

**نوع شواهد: عیب‌یابی عملیاتی گذشته، نه اثبات سود. نتیجه مالی NO-GO، معاملات واقعی غیرفعال، سرمایه مجاز صفر دلار.**

در سه روز کامل UTC از **۲۸ تا ۳۰ اکتبر ۲۰۲۶**، برنامه ثبت شش فرصت اسمی جمع‌آوری در روز را داشت: در مجموع **۱۸ فرصت**. خروجی کامل API برای اجرای زمان‌بندی‌شده GitHub بررسی شد؛ فقط **۹ اجرای واقعی** روی همان Workflow و شاخه main دیده می‌شود (**روزانه ۳ مورد**). این اختلاف به‌تنهایی ثابت نمی‌کند کدام نوبت cron مشخص اجرا نشده، حذف شده یا صرفاً دیر آغاز شده است.

در همین ۱۸ زمان بسته‌شدن کندل، فقط **۱ کندل چهارساعته با هر دو منبع WETH و cbBTC در یک ساعت بعد از بسته‌شدن ثبت شده** است: **۳۰ اکتبر، ساعت ۲۰:۰۰ UTC**. برای ۱۷ زمان دیگر شواهد کافی از دریافت به‌موقع جفت کندل نداریم. ثبت فایل پس از بسته‌شدن، زمان اولیه انتشار داده در سرویس‌دهنده یا امکان اجرای معامله را ثابت نمی‌کند.

در نقطه برش ساعت ۱۲:۴۹:۴۵ UTC روز ۱ نوامبر، ۲۲ فایل معتبر در آرشیو بررسی شده است. ۱۴ شناسه اجرای گزارش‌شده در فایل‌ها با فهرست ۱۷ اجرای API تطبیق دارد؛ این تطبیق هنوز جایگزین راستی‌آزمایی مستقل لاگ هر Job نیست. در این گام **هیچ کندل جدید، بک‌تست جدید، معامله واقعی، روز Paper Trading تأییدشده یا اجازه سرمایه‌گذاری** ایجاد نشده است.

**اقدام بعدی:** ایجاد ساعت مستقل برای جمع‌آوری روی میزبان مشخصی که مجوز استفاده از آن داده شود؛ بدون تغییر پروژه‌های دیگر، با همان قرارداد SHA و جلوگیری از داده تکراری. دو cron فعلی هر دو روی GitHub Actions اجرا می‌شوند و مستقل نیستند. اگر آزمایش منجمد قبلی دیگر تکمیل‌شدنی نباشد، باید جمعیت آزمایشی جدید از پیش ثبت شود و شروع قبلی بازنویسی نشود. هزینه واقعی معامله ۲۰ دلاری با ۶۰ ثانیه تأخیر هم همچنان ناشناخته است. الزام **۱۹۴ کندل پیوسته** و **حداقل ۹۰ روز واقعی Paper Trading** قابل ساختن با داده گذشته نیست.

هیچ کلید، تراکنش، پرداخت API یا دور زدن محدودیت 429 انجام نشد. [Issue #68](https://github.com/DashSaman/Arz/issues/68).
