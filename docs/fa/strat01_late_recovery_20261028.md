## تشخیص Schedule در ثبت‌های بعدی

از این مرحله، `strat01_base_identity_forward.py` در ثبت‌های **آینده** اگر داخل GitHub Actions اجرا شود، `GITHUB_EVENT_NAME` (برای تمایز `schedule` و `workflow_dispatch`)، `GITHUB_RUN_ID`، Run Attempt، Commit SHA و URL اجرای واقعی را در `runner_provenance` ذخیره می‌کند. حسابرس این فراداده را از نظر شکل و تطابق URL بررسی می‌کند.

این فراداده از **محیط Runner گزارش می‌شود** و تا هنگام مقایسه مستقل با اطلاعات اجرای GitHub نباید `schedule_event_independently_attested=true` اعلام شود. ثبت‌های قدیمی بدون تغییر می‌مانند و فراداده آینده به آن‌ها تزریق یا Backdate نمی‌شود.
