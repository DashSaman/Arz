# نصب و بهره‌برداری

**تاریخ بررسی: 2026-10-13 به وقت UTC. سرمایهٔ آزمایشی: حداکثر $100. معاملهٔ واقعی: غیرفعال.** این راهنما مربوط به شبیه‌ساز پژوهشی بدون کیف پول است و روشی برای ساخت کیف پول، امضا، مجوز توکن، واریز، خدمات پولی یا سفارش واقعی ارائه نمی‌کند.

## ۱. نصب از نسخهٔ محلی مخزن

به Python **3.11 یا جدیدتر**، ماژول `venv` و پوستهٔ سازگار با POSIX نیاز است. از ریشهٔ مخزن اجرا کنید:

```bash
bash scripts/install.sh
```

[نصب‌کننده](../../scripts/install.sh) محیط `.venv` را می‌سازد، نسخهٔ پایتون را بررسی می‌کند، آزمون‌های محلی را اجرا و راهنمای CLI را نمایش می‌دهد. فرمان‌های دستی معادل آن:

```bash
python3 -m venv .venv
.venv/bin/python -c 'import sys; assert sys.version_info >= (3,11), "Python 3.11 or newer is required"'
PYTHONPATH=src .venv/bin/python -m unittest discover -s tests -v
PYTHONPATH=src .venv/bin/python -m arz --help
```

این مراحل وابستگی پروژه‌ای دانلود نمی‌کنند؛ اجرای اصلی فقط کتابخانهٔ استاندارد پایتون را می‌خواهد. پایتون و `venv` باید از قبل موجود باشند. برای فرمان‌های بعدی، فعال‌سازی محیط یا `pip install` لازم نیست. نمودارهای اختیاری اسکریپت جداگانهٔ گزارش پژوهش، به Matplotlib ازپیش‌نصب‌شده نیاز دارند؛ بدون آن نیز گزارش‌های عددی تولید می‌شوند. [مشخصات بسته](../../pyproject.toml).

## ۲. سه فرمان موجود

[CLI](../../src/arz/__main__.py) دقیقاً **`fetch`، `backtest` و `paper`** را دارد؛ فرمان زنده‌ای وجود ندارد. پیکربندی فقط `research` یا `paper` را می‌پذیرد و فرمان paper صریحاً حالت کاغذی را انتخاب می‌کند. نام راهبردها `trend`، `momentum` و `mean_reversion` است.

مسیر پیکربندی، دادهٔ ورودی، وضعیت بازراه‌اندازی و خروجی باید متفاوت باشد. CLI برخورد مسیرهای یکسانِ حل‌شده و نام‌های موجودِ اشاره‌کننده به یک فایل را رد می‌کند. گزارش ممکن است در مسیر انتخابی جایگزین شود؛ برای نگهداری خروجی اجراهای متوالی، نام گزارش متفاوت انتخاب کنید. Git فایل‌های محلی `runtime/` را نادیده می‌گیرد؛ این رفتار مجوز نگهداری داده نیست.

## ۳. دریافت دادهٔ تاریخی مجاز

پس از بررسی شرایط دسترسی و نگهداری مربوط، درخواست محدود دادهٔ عمومی چنین است:

```bash
PYTHONPATH=src .venv/bin/python -m arz fetch \
  --config configs/research.json --limit 1000 \
  --output runtime/market_4h.csv
```

[اتصال داده](../../src/arz/connectors.py) فقط درخواست HTTPS **GET** به میزبان ثابت تحلیلی `api.geckoterminal.com/api/v2/` می‌فرستد. تغییرمسیرها دوباره بررسی می‌شوند و مسیر مظنه، سواپ یا امضا وجود ندارد. پیکربندی بررسی‌شده، WETH/USDC روی Base و کندل چهارساعته را ثابت می‌کند. `--limit` برای هر درخواست 1 تا 1,000 ردیف می‌پذیرد؛ درخواست جدید، کل مجموعه‌دادهٔ قدیمی را خودکار بازتولید نمی‌کند.

خروجی شامل CSV نرمال‌شده و فایل‌های جانبی `.raw.json` و `.provenance.json` است. منشأ داده، درخواست، زمان مشاهده/تکمیل، هویت‌ها، کنترل کیفیت و هش دادهٔ خام/نرمال‌شده را ثبت می‌کند. `--before` اختیاری، زمان یونیکس نامنفی است؛ تکمیل کندل با زمان زودترِ این مرز و زمان مشاهده سنجیده می‌شود.

ستون‌ها `ts,open,high,low,close,volume` هستند؛ `ts` شروع بازه به وقت UTC است. کندل بدساخت، نامتناهی، ناسازگار، تکراری، نامرتب، مفقود یا ناتمام رد می‌شود. هویت توکن‌های استخر در فراداده بررسی می‌شود. هش، بایت‌ها را مشخص می‌کند و حقیقت اقتصادی دادهٔ ارائه‌دهنده را تضمین نمی‌کند.

تا تعیین حقوق، دادهٔ خام و نرمال‌شدهٔ ارائه‌دهنده **برای بازتوزیع عمومی همراه مخزن نیست**. تکرار دقیق به ورودی مجاز با همان checksum نیاز دارد. [ارزیابی دسترسی و داده](dex_access.md)، از جمله ابهام ذخیره و نگهداری، ملاک است؛ عمومی‌بودن مسیر، مجوز نیست.

## ۴. شبیه‌سازی تاریخی آفلاین

```bash
PYTHONPATH=src .venv/bin/python -m arz backtest \
  --config configs/research.json --data runtime/market_4h.csv \
  --strategy trend --output runtime/backtest_trend_4h.json
```

فرمان، دادهٔ محلی را می‌خواند و اجرای سیگنال قبلاً محاسبه‌شده را در قیمت بازشدن کندل بعد با هزینه‌های فرضی مدل می‌کند؛ سفارشی ثبت نمی‌شود. خروجی شامل هویت ورودی/پیکربندی/کد/راهبرد، پرتفوی، اجراها، رویدادها، معاملات بسته، ارزش حساب و معیارهای توصیفی است. `execution_class=HISTORICAL_SIMULATION` و `prospective_observation=false` نوع شاهد را تعیین می‌کنند، حتی اگر برچسب mode متفاوت باشد.

[اسکریپت پژوهش](../../scripts/run_research.py) ارزیابی زمانی رو‌به‌جلو، تنش هزینه، معیارهای مقایسه و manifest می‌سازد. استفادهٔ دوباره از holdout برای حساسیت‌سنجی، شاهد مستقل جدیدی نیست. تفسیر نتیجه همچنان به مجوز داده، تاریخ کافی و محدودیت مدل وابسته است.

## ۵. مشاهدهٔ کاغذی محدود و آینده‌نگر

```bash
PYTHONPATH=src .venv/bin/python -m arz paper \
  --config configs/paper.json --strategy trend \
  --state runtime/paper_trend_4h.state.json \
  --samples 3 --sleep 20 \
  --output runtime/paper_trend_4h_observations_001.json
```

`--samples` به **1 تا 20** و `--sleep` به **1 تا 60 ثانیه** محدود است. نمونهٔ بالا سه مشاهده با دو مکث 20ثانیه‌ای، به‌اضافهٔ زمان درخواست‌ها، جمع می‌کند. این یک سرویس شبانه‌روزی، زمان‌بند، اتصال تلگرام یا آزمایش چند‌هفته‌ای نیست.

اولین مشاهدهٔ معتبر، تاریخ را بدون معاملهٔ تاریخی آماده می‌کند. پردازش بعدی به دقیقاً یک کندل بستهٔ جدید و مجاور و تاریخ مشترک بدون تغییر نیاز دارد. در بازهٔ چهارساعتهٔ پیش‌فرض، مشاهدهٔ کندل جدید برای اجرای کاغذی باید حداکثر **90 ثانیه** پس از بسته‌شدن باشد. دادهٔ سالمِ بدون کندل جدید می‌تواند `NO_NEW_COMPLETED_BAR` برگرداند؛ کندل مفقود، دادهٔ کهنه، مشاهدهٔ دیرهنگام، اصلاح تاریخ یا خطای شبکه می‌تواند توقف ماندگار بسازد. [پیاده‌سازی paper](../../src/arz/paper.py).

[پیکربندی پیش‌فرض paper](../../configs/paper.json) اکنون با بک‌تست چهارساعته هماهنگ است. [پیکربندی تشخیصی یک‌دقیقه‌ای](../../configs/paper_1m_diagnostic.json) برای آزمایش قبلیِ ناموفق حفظ شده است: میان 100 ردیف برگشتی، دو بازهٔ مفقود شناسایی شد. تاریخ آن نباید معاملهٔ کاغذی موفق چهارساعته نام‌گذاری شود.

آزمون اتصال مستقل چهارساعته، **چهار مشاهده طی حدود 75 ثانیه، بدون کندل بستهٔ جدید، بدون اجرا و با ارزش حساب شبیه‌سازی‌شدهٔ $100** داشت. [شاهد اتصال](../../reports/paper/connectivity_smoke.json). این فقط مشاهده‌ای کوتاه از اتصال/وضعیت است؛ نه عملکرد واجد سطح 4 و نه کارکرد مستمر.

## ۶. ادامهٔ همان آزمایش

استفاده از همان `--state` با هویت یکسان، **ژورنال نسخهٔ ساختار 2** را بازیابی می‌کند. [بازیابی](../../src/arz/engine.py) تمام گام‌ها و توقف‌های ثبت‌شده را بازپخش و سپس دفتر حساب، تاریخ، ریسک و سیگنال معلق را کامل مقایسه می‌کند. checksum وضعیت و پوشش بیرونی نیز باید سازگار باشد.

[هویت آزمایش](../../src/arz/provenance.py) شامل پیکربندی، کلاس/منبع/تنظیمات/پارامترهای راهبرد، همهٔ فایل‌های اجرایی `src/arz/*.py` و `sys.version` پایتون است. تغییر کد، ساخت مفسر، پارامتر یا پیکربندی ممکن است ژورنال قبلی را ناسازگار کند. برنامه ناسازگاری را رد می‌کند و خودکار مهاجرت، بازنشانی بودجه یا پاک‌کردن خطا انجام نمی‌دهد.

هنگام ناسازگاری، ژورنال و گزارش اصلی را حفظ کنید. مهاجرت یا آزمایش تازهٔ جداگانه و بررسی‌شده باید سابقهٔ شکست و هویت‌های آن را نگه دارد. موجودی یا رکورد خطا را ویرایش نکنید و با وضعیت تازه شکست را پنهان نکنید. سقف خواندن ژورنال 20,000,000 بایت و سقف بازپخش 10,000 فرمان، بررسی صریح بایگانی را لازم می‌کند؛ مقیاس‌پذیری طولانی‌مدت آزموده نشده است.

## ۷. خواندن توقف و ارزش‌گذاری

**هم `fault` و هم `result.halt_reason`** را بخوانید؛ متن status کافی نیست. خطای خارجی paper همهٔ پیشروی سفارش‌ها، حتی خروج شبیه‌سازی‌شده، را متوقف می‌کند. مشاهدهٔ معتبر بعدی همچنان می‌تواند بدون اجرا، `valuation.equity`، `as_of_close`، `observed_at`، `age_seconds` و `stale` را تولید کند. این ارزش‌گذاری مظنهٔ قابل‌اجرا نیست.

عملکرد دفتر حساب با `ending_equity_as_of_close` و `equity_scope` تاریخ‌گذاری می‌شود و نباید ارزش فروش تازه معرفی شود. توقف ناشی از حد ریسک، خرید تازه را می‌بندد و ممکن است در گام بعد خروجِ مشروط را امتحان کند. حداقل سفارش، نقدشوندگی، کارمزد، شبکه و سقف تعداد روزانه می‌توانند مانع خروج شوند. قطع فرایند جمع‌آوری، موقعیت را نمی‌بندد و موفقیت آزمایش را ثابت نمی‌کند.
