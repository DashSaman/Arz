# پیگیری V6 — بستن پاسخ‌های خطادار HTTP

CI نهایی PR92 در Python 3.14 سه ResourceWarning مربوط به پاسخ مصنوعی `HTTPError` نشان داد. این هشدارها به‌تنهایی نشت اتصال واقعی را اثبات نمی‌کنند: fixture بدون stream پاسخ ساخته شده بود و CPython یک stream حافظه‌ای ایجاد می‌کرد. با این حال بررسی `Probe.fetch` نقص واقعی مالکیت منبع را نشان داد؛ مسیر `HTTPError` خطا را تبدیل می‌کرد، بدون آنکه پاسخ را صریح ببندد.

این اصلاح پاسخ خطادار را پیش از انتشار همان خطای محدودشدهٔ HTTP می‌بندد. تصمیم توقف ارائه‌دهنده پیش از پاک‌سازی حفظ می‌شود و رگرسیون موجود از پاسخ حافظه‌ای صریح استفاده می‌کند که بسته‌شدن آن باید اثبات شود. درخواست، redirect، allowlist، retry، اعتبارنامه، timestamp، مقدار بازار و معیار مالی تغییر نکرده‌اند. آزمون‌ها مصنوعی‌اند و اتصال ارائه‌دهنده ایجاد نمی‌کنند.
