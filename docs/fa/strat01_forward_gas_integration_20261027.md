# Arz — ثبت خودکار منبع هزینه L1/L2 هم‌بلاک برای آینده‌نگر Base

**تاریخ: ۲۷ اکتبر ۲۰۲۶؛ پژوهشی؛ NO-GO و معامله واقعی DISABLED**

بعد از بررسی واقعی هزینه Base در [PR #52](https://github.com/DashSaman/Arz/pull/52)، این مرحله به `scripts/strat01_base_identity_forward.py` قابلیت دریافت *هم‌بلاک* داده هزینه را افزود تا در جمع‌آوری‌های آینده هر چهار ساعت، علاوه بر دو بازار WETH و cbBTC، هزینه فرضی شبکه نیز سند داشته باشد.

## دقیقاً چه چیزی ذخیره می‌شود؟

- `l2_basefee_per_gas_wei`: مقدار `baseFeePerGas` همان بلاک Base که دو Quote خواندنی از آن گرفته شده است.
- `l1_upper_bound_wei`: پاسخ GasPriceOracle رسمی Base به `getL1FeeUpperBound(uint256)` برای **اندازه unsigned فرضی ۳۰۰ بایت**؛ این مقدار کارمزد واقعاً پرداخت‌شده نیست.
- `gas_oracle_first_seen_unix` و `gas_oracle_rpc_sha256`: زمان دریافت واقعی و هش پاسخ منبع.
- `actual_L1_fee_usdc`، `actual_L2_fee_usdc`، `actual_network_fee_usdc` و `actual_failed_attempt_cost_usdc`: عمداً **null** باقی می‌مانند، چون هیچ تراکنش واقعی ارسال نشده و گاز پرداخت‌شده مشاهده نشده است.

حد درخواست برای اجرای جدید هشت خوانش محدود است: دو Candle، سه درخواست Chain ID/Header، دو Quote و یک Oracle. خطای ۴۲۹/۵۲۹ سبب تلاش نامحدود نمی‌شود. زمان اجرای واقعی به‌عنوان `first seen` نوشته می‌شود؛ زمان اسمی Cron جای آن را نمی‌گیرد.

## شواهد تست

[GitHub Actions 40433266636](https://github.com/DashSaman/Arz/actions/runs/40433266636) با **۳۱ تست متمرکز و ۱۰۴۵ تست کل مخزن PASS** اجرا شد؛ همان مجموعه‌ها هم‌پوشانی دارند. سناریوهای جدید، پاسخ سالم Oracle، نبود Base Fee، پاسخ ۴۲۹ و ممنوعیت تبدیل آن‌ها به سود یا پرداخت واقعی را بررسی می‌کنند. ابزار جدید در این مرحله **هیچ درخواست شبکه تازه‌ای انجام نداد**؛ داده‌ای که در [گزارش ماشین‌خوان](../../reports/strat01/2026-10-27-forward-fee-source-integration.json) آمده صرفاً وضعیت کد/تست و آماده‌شدن پروتکل جمع‌آوری است.

## زمان‌بندی و مانع باقی‌مانده

Workflow اصلی ساعت **۰۰:۲۳:۲۰ UTC** وارد `main` شد؛ ۲۰ ثانیه پس از نوبت Cron ساعت ۰۰:۲۳، بنابراین آن نوبت را نمی‌توان تأیید کرد. نخستین نوبت بعدی **۰۴:۲۳ UTC** است و ممکن است در GitHub Actions با تأخیر اجرا شود. **تأیید اجرای واقعی و ثبت خودکار داده هنوز انجام نشده است.**

بعد از اولین اجرای موفق، باید به‌تدریج داده کندل‌های کامل و مدارک هزینه واقعی قابل‌اتکا، کارمزد Priority، اختلاف Quote تا Inclusion و ریسک Failure را جمع کنیم؛ فقط پس از رسیدن به پوشش کافی، استراتژی ثابت S0 و تأیید H2 را در برابر نقد/هولد و هزینه استرس بررسی کنیم.

**هیچ تضمین سود یا انجام خروج وجود ندارد. Paper روزهای سپری‌نشده را حساب نکنیم.**
