# Arz — اصلاح مسیر حسابرسی ثبت خودکار چهارساعته (۲۷ اکتبر ۲۰۲۶)

**مرحله STRAT-01، ایمنی نرم‌افزار و تمامیت داده؛ نه یک استراتژی سودده و نه تأیید سرمایه‌گذاری.**

## مشکل واقعی شناسایی‌شده

در نسخه قبلی `.github/workflows/strat01-base-forward.yml`، اجرای `schedule` فایل داده Base را با توکن داخلی GitHub به `main` Push می‌کرد. گمان می‌رفت `push` باعث اجرای جداگانه `strat01-investment-gate.yml` شود.

اما [مستندات رسمی GitHub در مورد GITHUB_TOKEN](https://docs.github.com/en/actions/concepts/security/github_token) تصریح می‌کند **Push انجام‌شده با `GITHUB_TOKEN` اجرای Workflow دیگری را با رویداد `push` فعال نمی‌کند**. بنابراین حتی اگر فایل آینده‌نگر ذخیره می‌شد، کنترل خودکار مالی ممکن بود اصلاً اجرا نشود.

## اصلاح اجرایی ثبت‌شده

اکنون خودِ Job زمان‌بندی‌شده این ترتیب را رعایت می‌کند: اعتبارسنجی کنترل‌های اصلی پروژه؛ یک Snapshot واقعی خواندنی کندل و Quote از هر دو بازار Base؛ اجرای مستقل `scripts/strat01_investment_readiness.py` روی فایل‌های حاضر؛ اعتبارسنجی مستقیم همان Snapshot تازه شامل UTC، وضعیت کندل، بازبینی تعارض و عدم ادعای Fill؛ تطبیق **SHA-256 دقیق فایل و زمان نخستین مشاهده** با Manifest گزارش؛ سپس Commit **هم‌زمان فایل داده و فایل گزارش تصمیم NO-GO**.

فایل‌های داده در `reports/strat01/forward/YYYYMMDDTHHMMSSZ.json` و گزارش‌های متناظر در `reports/strat01/audits/YYYYMMDDTHHMMSSZ.json` قرار خواهند گرفت. اگر `main` محافظت شده باشد یا Push شکست بخورد، **Artifact هر دو فایل** در همان اجرای Actions محفوظ می‌ماند. شکست حسابرسی پیش از Commit باعث جلوگیری از Push می‌شود. سرویس بیرونی جدید، کلید خصوصی، امضا، سفارش یا افزایش سرمایه اضافه نشده است.

کنترل مالی مبتنی بر `push` برای Push انسانی باقی می‌ماند، اما صحت‌سنجی داخلی ربات دیگر به رویدادی که GitHub آن را اجرا نمی‌کند وابسته نیست.

## آزمون و محدودیت

[GitHub Actions 40445177286](https://github.com/DashSaman/Arz/actions/runs/40445177286) با **۱۲۰۸ تست کامل موفق** شد. [ارزیاب مستقل 40445177280](https://github.com/DashSaman/Arz/actions/runs/40445177280) نیز **۱۴۳ تست مخصوص آمادگی سرمایه و ۱۲۰۸ تست کامل** را موفق گزارش کرد (هم‌پوشان).

تست‌های جدید ترتیب «حسابرسی قبل از Push»، تطبیق SHA/UTC، جداسازی دسترسی نوشتن، حفظ Artifact، تعارض قیمت دو Snapshot یک بازه، نبود دیتای زمان‌بندی‌شده و ممنوعیت برداشت سود و Paper از Quote را کنترل می‌کنند.

**این مرحله فقط صحت کد اصلاح‌شده را اثبات می‌کند. اجرای واقعی آینده Job زمان‌بندی‌شده و ذخیره فایل هنوز مشاهده نشده و تأیید نشده است.** نخستین نوبت محتمل بعدی در روز ۲۷ اکتبر، ساعت ۰۴:۲۳ UTC است؛ GitHub ممکن است آن را به تعویق بیندازد یا اجرا نکند.

### نتیجه و مرحله بعد

- منبع کندل‌های OOS هنوز برای حداقل ۱۹۴ کندل پیوسته در هر دو جفت آماده نیست.
- هزینه پرداخت‌شده واقعی L1/L2، اسلیپیج، MEV، شکست سفارش و معامله دنبال‌کننده با تأخیر ۶۰ ثانیه هنوز UNKNOWN است.
- ۹۰ روز واقعاً سپری‌شده Paper و بازده خالص هندسی مثبت تحت هزینه دوبرابر وجود ندارد.
- مرحله بعد تأیید اجرای واقعی Cron و ذخیره هم‌زمان فایل داده/حسابرسی و سپس جمع‌آوری پیوسته بازار است.

**تصمیم مالی NO-GO و معاملات واقعی DISABLED هستند. سود یا خروج تضمین‌پذیر نیست.**
